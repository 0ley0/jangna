## Platform

## Users
- **ผู้ใช้หน้าเว็บหลัก:** เจ้าของร้านออนไลน์ (SME ไทย) ที่จ้างคนแพ็ค/พนักงานรายวัน ใช้ **มือถือหรือโน้ตบุ๊ก** ปิดรอบเงินเดือน **เดือนละ 1–2 ครั้ง** — ไม่ใช่สาย HR ทำเงินเดือนเองเป็นครั้งคราว ต้องการหน้าตรวจตัวเลขที่ง่ายและมั่นใจก่อนกด "ปิดรอบ"
- **พนักงาน** (คนแพ็ค รายวัน รายชั่วโมง รวมแรงงานต่างด้าว) ไม่ใช้หน้าเว็บนี้ — ใช้ผ่าน LINE (LIFF) ไม่ต้องลงแอป; ภาษา ไทย / อังกฤษ / พม่า
- ผู้จัดการ/แอดมินร้านกรอกข้อมูลรายวัน (วันทำงาน ผลงานต่อชิ้น เงินเบิก จัดกะ) — บทบาทรอง ยังไม่ได้ยืนยันรายละเอียดการใช้งานประจำวัน

## Product Purpose
ให้ร้านเล็กจ่ายเงินเดือนคนแพ็ค/พนักงานได้ถูกต้องตามกฎหมายแรงงานไทย โดยไม่ต้องมีฝ่ายบัญชี: บันทึกงาน → คำนวณ → ตรวจ → ปิดรอบ → ออกสลิปและเอกสารยื่น สปส./ภาษี ความสำเร็จ = เจ้าของปิดรอบได้เองด้วยความมั่นใจว่าตัวเลขถูก และยื่นเอกสารตรงกำหนด

## Positioning
สิ่งที่คู่แข่ง HR ทั่วไปทำตามไม่ง่ายนัก (ยืนยันโดยเจ้าของโปรดักต์):
1. **แพ็ค = ลงงาน = เงินเดือน** ในระบบเดียว (ค่าแพ็คต่อชิ้น/กล่องไหลเข้าเงินเดือนอัตโนมัติ)
2. **ตัวเลขเงินเดือนตรวจย้อนได้ทุกบาท** (ทุกรายการมาจากไหน มีคำเตือน มี snapshot ของกฎหมายที่ใช้ รอบที่ปิดแล้วแก้ไม่ได้)
3. **เอกสารยื่น สปส./ภาษี ครบในที่เดียว** (สปส.1-10, ภ.ง.ด.1, สลิป พร้อมบอกข้อมูลที่ยังขาด)
4. **พนักงานใช้ผ่าน LINE ไม่ต้องลงแอป**

## Operating Context
- งานประจำเดือน: ปิดรอบ → ส่ง สปส.1-10 และชำระภายในวันที่ 15 ของเดือนถัดไป → ยื่น ภ.ง.ด.1 ภายในวันที่ 7 (ออนไลน์ถึง 15) → แจกสลิป
- ใช้ข้อมูลจริงที่สะเทือนเงินและกฎหมาย: เลขบัตรประชาชน เลขผู้เสียภาษี ที่อยู่ ค่าแรงขั้นต่ำตามจังหวัด/อำเภอ ฐานประกันสังคม
- UI สองภาษา (ไทย/อังกฤษ), ปีไทยแสดงเป็น พ.ศ.; ข้อความที่ส่งให้พนักงานใช้ภาษาของพนักงานคนนั้น
- ช่วงโหลดสูง: คนช่วงเซล 9.9–12.12 (ร้านออนไลน์)

## Capabilities and Constraints
- มีแล้ว: ลงบันทึกงานเอง, คำนวณเงินเดือน (engine เป็น pure function, กฎหมายเป็นข้อมูล effective-dated), รอบจ่าย draft→lock, สลิป PDF, ไฟล์ สปส.1-10 / ภ.ง.ด.1, กะงาน
- **ยังไม่มี:** ลงเวลาผ่าน LINE/LIFF, Pack station (สแกน+วิดีโอ), ส่งข้อความเข้า LINE — รอเปิด LINE OA
- ข้อจำกัดทางกฎหมาย: เงินเป็น `decimal`, รอบที่ lock แล้วห้ามแก้, ห้ามหักค่าจ้างอัตโนมัติ (บันทึกอย่างเดียว) — ดู `payroll.md`
- ยังไม่ตัดสินใจ/ยังไม่ยืนยัน: ค่าแรงขั้นต่ำเป็นข้อมูล draft (`verified: false`), รูปแบบไฟล์ สปส.1-10 ยังไม่ได้ทดสอบอัปโหลดจริง, สมมติฐานด้านกฎหมายแรงงานรอทนายยืนยัน

## Brand Commitments
- ชื่อ **จ้างนะ** (Jangna) โลโก้ใช้ภาษาไทยเป็นหลักเสมอ ธีมดีไซน์ปัจจุบันคือ Hearth (ครีม + เทอร์ราคอตต้า, ฟอนต์ Noto Sans Thai) — ที่เป็นอยู่แล้วในโค้ด ยังไม่ได้ให้ยึดเป็นข้อบังคับถาวร

## Evidence on Hand
- ยังไม่มีลูกค้าจริงและยังไม่ได้สัมภาษณ์ร้านออนไลน์ 10 ร้าน (อยู่ใน roadmap) — **ห้ามแต่งคำรับรอง ตัวเลขลูกค้า หรือผลลัพธ์ขึ้นเอง**
- มีข้อมูลเปรียบเทียบคู่แข่งและราคาร่างด้านล่างในไฟล์นี้ และเอกสารกฎหมาย/สูตรใน `payroll.md`

## Product Principles
1. **ตัวเลขต้องอธิบายได้** — ทุกยอดบนจอบอกที่มาและคำเตือนได้ ก่อนปิดรอบต้องตรวจง่าย
2. **ไม่ให้ทำผิดเงียบๆ** — ข้อมูลขาด/ผิดบอกชัดเจนว่าอะไร แก้ที่ไหน (ไม่ปล่อยให้ไฟล์ยื่นแบบออกผิด)
3. **เจ้าของร้านไม่ใช่ผู้เชี่ยวชาญบัญชี** — ภาษาธรรมดา ขั้นตอนสั้น ใช้งานจบบนมือถือได้
4. **ไทยก่อน แต่ไม่ทิ้งแรงงานต่างด้าว** — ทุกข้อความมีสองภาษา และฝั่งพนักงานรองรับพม่า
5. **ใช้ได้เดี่ยวๆ** — ไม่พึ่ง Ruam Talad หรือ LINE จนกว่าจะพร้อม

## Accessibility & Inclusion
- เป้าหมาย: **WCAG 2.1 AA** และ **ภาษาไทยอ่านง่ายบนมือถือ** (สระ/วรรณยุกต์ซ้อนกัน จึงไม่ควรใช้ตัวเล็กหรือสีจาง)
- แก้ผล audit แล้ว (2026-10-02): สีตัวอักษรรอง ปุ่มหลัก อวาตาร์ ผ่าน AA, พื้นที่กดบนจอสัมผัส ≥ 44px, รองรับ reduced-motion, แถวรอบจ่ายใช้คีย์บอร์ดได้

## รายละเอียดธุรกิจ (เดิม)

SaaS ลงเวลา + เงินเดือน ผ่าน LINE สำหรับ SME ไทยที่จ้างพนักงานรายวัน/รายชั่วโมง/ต่อชิ้น

- **กลุ่มแรก:** ร้านค้าออนไลน์ที่จ้างพนักงานแพ็คสินค้า (ค่าแพ็คต่อกล่อง/ชิ้น + รายวัน, คนช่วงเซล 9.9–12.12)
- **กลุ่มถัดไป:** ร้านอาหาร (กะ, service charge/ทิป, หลายสาขา)
- **จุดขาย:** "แพ็ค = ลงงาน = เงินเดือน" ในระบบเดียว ผ่าน LINE — คู่แข่ง HR ทั่วไปไม่ได้เจาะคนแพ็ค
- **โปรเจกต์พี่น้อง:** Ruam Talad (`../ruam-talad`, รวมสต็อก/ออเดอร์ Shopee/TikTok) → ส่งออเดอร์มาให้ Pack module ผ่าน API/webhook
  แต่ Jangna ต้องใช้งานเดี่ยวได้

- HumanSoft อาจทำฟีเจอร์ร้านอาหาร/คนแพ็คตาม → จุดต่างต้องลึกกว่า (Pack module + Ruam Talad)
